# diffskim

`git diff | diffskim | delta` drops the hunks that are only formatting, import shuffles, lockfiles or generated code. Deterministic, offline, no LLM.

On 30 merged agent-written pull requests from public TypeScript/JavaScript repositories, `git diff -M -w` with lockfiles excluded already cut 14,411 changed lines to 8,772. diffskim cut them to 8,437: **3.8% fewer lines than git's own flags overall, and none fewer on the median PR**. The gain is concentrated in pull requests that ran a formatter: on [evroon/bracket#1750](https://github.com/evroon/bracket/pull/1750) (a Prettier-to-oxfmt swap) it kept 181 of the 750 lines git kept. On most feature PRs it changes nothing, and on 7 of the 30 it keeps more lines than git (see Limits). Per-PR numbers and the script that measures them are in [bench/](bench/).

```text
$ diffskim 38a9241 bac9e33          # sanity-io/sanity#11754, in a clone of it
diffskim: 394 changed lines -> 78 kept (git diff -M -w + lockfile excludes: 91); folded lockfile 303, generated 13

@@ -1,3 +1,4 @@ [folded above: generated 13 lines]
+/* eslint-disable class-methods-use-this */
 // oxlint-disable-next-line no-unassigned-import
 import 'blob-polyfill'
 // oxlint-disable-next-line no-unassigned-import

$ diffskim --explain 38a9241 bac9e33
packages/sanity/test/cli/graphql/__snapshots__/gen3.test.ts.snap generated (13 lines): __snapshots__/
pnpm-lock.yaml lockfile (303 lines)
```

## Install

```sh
go install github.com/kova1max/diffskim@latest
```

This needs Go 1.24 or newer and a C compiler, because the TypeScript and JavaScript parsers ([tree-sitter](https://tree-sitter.github.io/)) are C. On macOS run `xcode-select --install` first. There are no prebuilt binaries yet.

## Usage

```sh
git diff main... | diffskim | delta    # filter any unified diff
diffskim main...                       # or let diffskim run git diff
diffskim --explain main...             # one line per fold, with its rule
diffskim --json main...                # summary and folds as JSON
```

- Arguments other than diffskim's own options go to `git diff`. With no arguments and nothing piped in, diffskim runs `git diff`.
- The skimmed diff goes to stdout and a one-line summary goes to stderr (`-q` turns it off). When diffskim runs git itself, the summary also gives the git built-ins baseline: `git diff -M -w` with every lockfile excluded.
- The output is still a patch. `git apply --check` accepts it against the old side, and applying it applies only the kept changes. Kept hunks keep their real line numbers.
- Every hunk heading that follows folded changes says what was folded: `[folded above: import-only 2 lines]`. Whitespace-only lines folded out of a hunk that is otherwise kept are named in that hunk's heading as `[folded here: whitespace-only 12 lines]`. delta and plain `less` show these headings.
- Exit status: 0 on success, 1 on an error (git failed, the input is not a unified diff), 2 on bad usage.

## What gets folded

| Rule | Folds | Example | Does git already do it? |
|---|---|---|---|
| `lockfile` | the whole file, for 24 lockfile names (`diffskim --lockfiles` lists them) | `pnpm-lock.yaml`, `go.sum`, `Cargo.lock` | With pathspecs: `git diff -- . ':!pnpm-lock.yaml'` |
| `generated` | the whole file, when its first five lines say `DO NOT EDIT`, `@generated` or `<auto-generated`, `.gitattributes` marks it `linguist-generated`, or its name is `*.pb.go`, `*_pb2.py`, `*_pb2.pyi`, `*_pb2_grpc.py`, `*.min.js`, `*.min.css`, `*.js.map`, `*.css.map`, `*.snap` or under `__snapshots__/` | `// Code generated by protoc-gen-go. DO NOT EDIT.` | No. GitHub collapses `linguist-generated` files in its UI. |
| `whitespace-only` | removed and added lines that are equal once leading and trailing whitespace is trimmed and other runs of whitespace are collapsed to one space, paired up (longest common subsequence) inside each run of changed lines. Whitespace removed between two words or inside a string is kept. Never in Python, YAML, Makefiles, Markdown or other whitespace-sensitive files, and never in TypeScript or JavaScript files whose contents are available, where the format rule decides instead | re-indenting a block | Mostly, `git diff -w`, which also folds it in whitespace-sensitive files and folds whitespace removed between words |
| `import-only` | changed lines that are all import statements and only reorder or re-wrap them: within each hunk, the touched statements must import the same bindings from the same sources on both sides. An added, removed or changed import, source or binding is kept. Imports that only run code (`import './polyfill'`, Go `_` imports) must stay in the same order. TypeScript, JavaScript and Go. | sorting the imports of a file | No |
| `format-only` | changed lines whose syntax tree is the same: quote style, semicolons, trailing commas, line wrapping, JSX text wrapping. TypeScript and JavaScript only. | a Prettier run | No |

The import and format rules read both versions of each file from the git repository you run diffskim in, and only use them when they match the diff line for line. A diff piped in from somewhere else (for example `gh pr diff`) still gets the lockfile, generated and whitespace rules; the summary says how many lines the other rules could not check.

## Why this instead of

- **`git diff -M -w -- . ':!*.lock'`**: use it. It is the baseline above, and it removes most of what diffskim removes. diffskim adds import-only and format-only folds, generated-file detection, and output that is still a patch.
- **[meat](https://github.com/boldsoftware/meat)**: the same stdin-to-stdout shape, but it asks an LLM what to cut. diffskim is meat without the model: rules you can read, the same answer every run, no network.
- **[bottercode/diffsift](https://github.com/bottercode/diffsift)**: classifies TypeScript/JavaScript format, rename and move changes in a report. diffskim gives you a diff to read instead of a report. Credit to it for the idea.
- **[git-pkgs/review](https://github.com/git-pkgs/review)**: detects mechanical changes in a patch and describes them in prose. Same idea, prose instead of a diff.
- **[hunk](https://github.com/modem-dev/hunk)**: a diff viewer. Collapsing generated files and lockfiles there is [an open request](https://github.com/modem-dev/hunk/issues/462).

## Limits

- On most pull requests the gain over `git diff -M -w` plus lockfile excludes is small or nothing (the median PR above keeps as many lines as git). diffskim pays off on formatter runs, import churn and generated files.
- The import and format rules cover TypeScript and JavaScript; Go gets the import rule only. Everything else gets only the lockfile, generated and whitespace rules.
- The format rule folds a hunk only when both syntax trees match exactly. Formatter changes that alter the tree are kept: added or removed parentheses, `x => x` becoming `(x) => x`, quotes added to object keys. So are hunks that tree-sitter cannot parse, such as JSX text with a bare `&`.
- Whitespace-only lines are paired inside one hunk. When code is moved and re-indented across hunks, `git diff -w` re-diffs the whole file and finds pairs diffskim does not.
- In TypeScript and JavaScript only the format rule folds whitespace, and only when a whole run of changed lines has the same syntax tree, so re-indented lines next to a real change are kept. On 7 of the 30 benchmark PRs diffskim keeps more lines than `git diff -M -w`; on [calcom/cal.diy#22974](https://github.com/calcom/cal.diy/pull/22974) it keeps 700 lines where git keeps 378.
- Nothing scores risk. diffskim only hides; it never says a kept hunk is safe.
- A fold that hides a real change is a bug. Please [open an issue](https://github.com/kova1max/diffskim/issues) with the diff, or with the repository and commit range.

## Why I built this

Agent-written pull requests are long, and much of their length is mechanical: formatter runs, sorted imports, regenerated files, lockfiles. I wanted to read only the part that needs a human, in the pager I already use, without asking a model to decide what I may skip. The benchmark is in the repository so you can check how much that really saves.

## Contributing

Run `go test ./...` and `bench/run.sh` (it needs git, Go, Python 3 and, the first time, network access). Pull requests that add a rule should add a benchmark PR where the rule matters and tests for the changes it must not fold.
